Class APIGuildBounties

Kick Bounties - a server gets one post for every Kick Bounty (bounties.kick.com) of the player types it picks, and that post is edited when the bounty is claimed ("Claimed by ...") or runs out ("Expired"). Several bounties due at once (for example when the server first turns it on and some are already active) arrive as ONE message with one ping.

Behind the kickBounties launch flag: every method answers 403 until it is beta/public for the caller. The feature is free. The webhook identity is Premium Plus (CustomWebhooks); data.limits.webhook says whether the server has it, so the form can lock the control.

sendTestBountyNotification

  • sendTestBountyNotification(__namedParameters): Promise<WebResponse<string>>

  • Send a test post to the saved channel. Never pings and writes no "already sent" record, so it never stops a real post. Uses the newest open bounty, else the newest of any state (so an ended one previews its "Claimed by" look), else a sample. With Premium Plus it posts with the saved webhook identity.

    400 when the page is off, has no channel, or the channel is gone / missing permissions (View Channel, Send Messages, Embed Links); 403 for the launch flag or the vote gate (isVoteRequired(error)); 429 { code: 'rate_limited', message, retryAfterSeconds } - one test per server every 25 seconds, with a Retry-After header too; 503 when the server's shard cannot be reached. data is a message to show as-is.

    POSTs the collection for the same reason sendTestBadgeNotification does: one segment is the only shape the API's catch-all guild routes cannot claim.

updateGuildBounties

  • updateGuildBounties(__namedParameters): Promise<WebResponse<GuildBountiesData>>

  • Save a server's setup, field by field - omit one to leave it unchanged. Answers with the whole setup.

    400 names the field on a bad value. playerTypes must be a non-empty list of creator, viewer, developer - to receive nothing, send enabled: false. 403 "Premium required" when a server without Premium Plus sends a webhook with a value; null is always accepted, so a lapsed server can clear it. A webhook username must be 1-80 characters and cannot contain "discord" or "clyde"; avatarUrl must be https.
